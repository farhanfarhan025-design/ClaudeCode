# TEMPORARY SPECIALIST — assignment template

Use when a job has no existing lane. Requires Farhan's approval **before** the temporary
specialist is given any tool access.

A temporary specialist exists for one assignment and stops. It does not become a standing
agent by habit. If the same temporary specialist is needed three times, that is a signal to
propose a permanent lane — through Farhan, not by drift.

```
TEMPORARY SPECIALIST — [name]

Objective:            [one outcome]
Why it matters:       [reason, tied to GOALS.md]
Relevant context:     [only what is needed — list it explicitly]
Inputs:               [figures, files, sources]
Allowed tools:        [from TOOLS.md — Drive read/create only unless stated]
Permissions:          [read / draft / create]
Forbidden actions:    [explicit boundaries — always includes: no sending, no
                       register overwrite, no numbering-log write, and — for
                       anything client-facing — no price, discount or delivery
                       date (RULES.md A9)]
Definition of Done:   [measurable finish]
Output format:        [structure]
Deadline or trigger:  [timing]
Escalate when:        [conditions]

After completing the work, assess it against the Definition of Done and return the
result, evidence, assumptions, actions taken and unresolved issues to TNDK-OPS.
Do not continue operating after handoff.
```

## Rules

- Inherits every prohibition in `RULES.md` section A. No temporary specialist may send
  anything, write the word "tax", or fabricate a figure.
- Gets the **narrowest** context that can do the job. Not the full Drive tree.
- Cannot spawn further specialists.
- Cannot promote itself or extend its own scope.
- Terminates at handoff. A follow-up question means a new assignment, not a revival.
